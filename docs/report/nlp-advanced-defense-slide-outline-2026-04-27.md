# Текст к слайдам (защита NLP Advanced)

Источник цифр и методики: `docs/report/nlp-advanced-final-report-2026-04-26.md`. Дек: `docs/report/nlp-advanced-defense-slides.html` (**11** слайдов).

---

Слайд 1. Титульный

Интеллектуальная система поддержки научного исследования на основе GraphRAG. NLP Advanced. Не чат «в общем», а система для корпуса статей: граф, цитаты, трассировка агента, бенчмарки. Подзаголовок: GraphRAG, агентный поиск и проверяемые ответы.

---

Слайд 2. План защиты

Цель и задачи → стек → что сделано (архитектура, агент, метрики, демо) → выводы → вопросы и развитие. Упор на середину.

---

Слайд 3. Цель и задачи проекта

Сквозная GraphRAG-система: корпус → граф → retrieval → ответы с цитатами. Задачи: нормализация и извлечение под граф, векторный и графовый доступ, честная оценка качества.

---

Слайд 4. Какие технологии использовались

Python, FastAPI, графовый оркестратор агента. Postgres + Neo4j + Qdrant. LLM-пайплайн извлечения и tool-calling. React, Phoenix/OpenTelemetry. Оценка: автоматические бенчмарки и формальные сценарии агента.

---

Слайд 5. Архитектура системы

Ingest отдельно от чата: данные готовятся заранее, runtime только читает. Один research-агент с tools к трём хранилищам. При необходимости — режим с маршрутизатором и подзадачами. Authorship в графе явно.

---

Слайд 6. Инструменты агента и системный промпт

Основной агентный режим: каталог инструментов и схемы аргументов. Промпт: область ответа по корпусу, маршрутизация вопрос→инструмент, лимит фан-аута, один явный финальный шаг ответа с цитатами.

---

Слайд 7. Те же тулзы как Python-функции

Сигнатура + docstring = контракт для модели. Примеры: семантика по чанкам, read-only Cypher, полнотекст по работам.

---

Слайд 8. Демонстрация системы

Вопрос по корпусу → тулзы → ответ с цитатами; по желанию trace. Связка с метриками: не только отчёт.

---

Слайд 9. Основные результаты и выводы

Срез отчёта: извлечение под граф, retrieval, многошаговый граф (recall vs precision), агент 10/10 suite, p95, судья. Слабые цифры на перефразе утверждений — осознанно, как строгий контроль.

---

Слайд 10. Выводы

**Бенчмарки.** Одних P/R/F1 и ROUGE-L недостаточно для PDF-конвейера: без договорённости «как сравниваем» цифра обманчива. Нужны нормализация текста и полевые эвристики в скриптах оценки (идентификаторы, IoU секции References, fuzzy методов/датасетов, режимы перефраза в эталоне кейса). Иначе бенчмарк не про постановку. Параллельно — смотреть датасет и провалы, не только агрегаты. На старте: черновой эталон с **сильной LLM по PDF/MD**, потом ручное сужение — быстрее первый покрывающий набор кейсов.

**Агент и UI.** Смотреть ответ вместе с трассой; финальный шаг ответа хрупок при смене промпта или графа. Граф на экране — отдельно от корректности Neo4j (масштаб, шум).

---

Слайд 11. Накопленное и дальнейшие планы

Подзаголовок: три направления дорожной карты — **агенты** (один исследовательский контур и инструменты; при росте сложности — маршрутизатор и подзадачи; поиск инструмента по смыслу), **контекст и бенчмарки** (суммаризация длинных диалогов, расширение регрессионных наборов, связка с трассами и провальными кейсами), **продукт** (движок графа в UI, устойчивый ingestion и возобновляемость, дедуп похожих работ и сущностей). Финальная цитата их суммирует; справа — иллюстрация дорожной карты.

## Справка к слайду «Выводы» (метрики по полям, для вопросов комиссии)

Ниже — обобщённая схема того, как в контуре автоматической оценки задаются метрики. В ответе всегда: **поле → режим сравнения → агрегат → порог из эталона кейса**.

### Общие приёмы

- **Exact** после нормализации (пробелы, регистр, канонизация DOI, варианты дефисов/кавычек в абстракте).
- **Текст:** ROUGE-L F1 по словам, multiset token F1, containment токенов префикса абстракта; **difflib** по авторам — мягкий сигнал (слой текстовых метрик «layer-1»).
- **Множества:** P/R/F1 по строкам-идентификаторам (arXiv, DOI из полей и regex в сырой ссылке).
- **References:** IoU множеств номеров строк; overlap записей через greedy match по Jaccard токенов строки (отдельный harness для секции литературы).
- **Семантические методы/датасеты для графа:** нормализация, порог уверенности модели, exact / substring / word Jaccard ≥ 0.55 на длинных фразах (слой «layer-2»).
- **Утверждения / концепты / темы:** совпадение по id, якорная подстрока, при необходимости rouge или эмбеддинг-сходство с порогами в эталоне.

### Задел / слабые места выбора

- ROUGE/token не заменяют человека на научном перефразе; NLI/human — редкие точечные дополнения.
- difflib по ФИО может «перещадить»; смотреть в паре с set-F1.
- Fuzzy layer2 не ловит синонимы без пересечения слов.
- Sample DOI/arXiv — не полное сравнение всей библиографии.
- Эмбеддинг в claims чувствителен к модели и порогу — калибровать по валидации.

Шаблон ответа: поле в эталоне → режим → precision/recall/F1 / IoU / ROUGE → порог → указать модуль скоринга в репозитории (при необходимости уточнить по слоям layer-1 / layer-2 / harness / claims).
