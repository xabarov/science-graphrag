# References resolution: graph-backed lane (stub)

## Goal

The v1 harness today reads **`synthetic_predictions`** embedded in `gold.json`. The next step is a **Neo4j-backed resolver** that produces the same `(raw_citation_span_id → canonical_key)` rows from a live graph.

Until that code exists, the repo ships a **placeholder lane** so CI and docs can reference the same CLI shape.

## Gold fields

| Field | Role |
|-------|------|
| `synthetic_predictions` | Deterministic harness (default `--suite` runs) |
| `graph_stub_predictions` | Optional list with the same schema; **today** a copy of synthetic data for `refs_mini_*` cases |

When the real resolver is wired, `graph_stub_predictions` will be removed or generated by a fixture script from graph output.

## CLI

```bash
science-graphrag-references-resolution-benchmark tests/fixtures/benchmarks/references_resolution \
  --suite --tier refs_graph_stub \
  --graph-stub-lane \
  --json-out eval/results/current-references-resolution-graph-stub.json
```

`--graph-stub-lane` reads `graph_stub_predictions` when present, otherwise falls back to `synthetic_predictions`.

Tier **`refs_graph_stub`** lists the same three cases as `refs_mini` (`case_tiers.json`).

## Authoritative summary

The main `benchmark-metrics-summary.json` still points at the existing contract + mini JSON paths. Add a graph-backed artifact to the aggregator only after the resolver is real and stable.
